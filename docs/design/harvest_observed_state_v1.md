# Jev 收割参数：基于可见状态的可选适配

本分支从正在实验的 `ac92e1d` 分离，初始离线原型保存于提交 `71b1a44`。
目前已经接入 Jev 的条件参数规划器，**默认关闭**，纯 Jev 与继承该规划器的
Hybrid 均可使用。当前 78 场 Jev 实验仍在冻结的另一个 worktree 中运行，不受
本分支改动影响。没有修改 Hybrid updater、Prompt 模板、任务、任务验收器或
原生工具。开启后参数问题中的工具合同会增加实际状态限制及其证据，这是明确的
候选接口变更，不能冒充与旧实验完全同一输入。

启用配置：

```json
{
  "parameter_strategy": "tool_contracts_v2",
  "harvest_state_policy": "harvest_observed_state_v1"
}
```

省略 `harvest_state_policy` 保留原行为。错误策略名、不兼容参数策略会在模型
选择前拒绝；原生 LLM 不能启用这个 Jev 参数适配选项。

## 直接证据与范围

冻结的 12 个历史场景中有 447 次收割返回
`All ridges must be planted before harvest`。这些请求选择的范围已经出现在
此前成功返回的 `harvested_ridges` 中；相关原始结果也实际进入了 Jev HTTP 输入。
原生 `TractorApp.harvest` 检查的是所选范围内的 `planted`，不是要求整个农场仍然
全部已种植。成功收割使所选垄 `planted=False`。因此该样本存在可由公共反馈
识别的参数前置条件冲突，而非反馈未送入模型。

这不是模型内部原因的证明，也不表示所有循环都具有同一个原因。

## 原型合同

- 输入是单次 episode 内按 `event_id` 严格排序的公开事件、已声明的垄界与作业宽度。
  不读取模拟器、checkpoint、oracle 或任务评分字段。
- 成功且实际执行的收割反馈只排除返回的 `harvested_ridges`。不从请求范围推定
  全部执行成功，不从 LLM 摘要推定事实。原始结果与事件 ID 随规则保留。
- 公开范围查询若明确返回布尔 `planted`，可更新限制；不将 NDVI、生育阶段或
  `harvested=False` 转换为已种植。
- 播种/补种移除受影响垄的旧限制；这仅表示需要重新判断，**不证明成熟可收**。
  模糊的播种错误也保守撤销相关限制，避免部分执行后永久误封。
- 整地、环境通知、显式状态失效事件撤销旧限制。没有解释通知文本的隐含语义。
  这是保守策略，可能使原先已知的无效范围重新出现。
- 未知垄仍保留。起点与终点共享同一份限制；终点不小于起点，不超过既有每趟宽度，
  也不会跨过中间已排除垄。不把整片范围缩成一个自动选择的动作。
- 无合法范围时返回 `needs_context`。不自动 FINISH、不执行刷新工具，不替模型
  选择其他动作。

当前作物状态失效路径依据该提交中 FAIRY 的种植、补种、起垄和收割实现审查。
若增加其他可以改变 `planted` 的工具、外部修改或跨 episode 历史，必须补充失效
合同；本原型不声称适用于任意农场工具或任意外部并发修改。

## 离线结果

初始原型 24 项测试通过，覆盖空状态、整段候选覆盖、范围中间空洞、上下界、起止顺序、
重播/补种、错误与未执行区分、显式观测覆盖、通知/生命周期失效、非法数据、
输入不变和全范围排除。测试禁止网络访问。

对冻结的 12 份 trace，审查发生在每次原始工具选择请求之前，不使用之后的结果
来构造该次候选。共检查 554 次历史收割：

| 历史调用结果 | 次数 | 原参数在新菜单中的情况 |
| --- | ---: | --- |
| 已收割范围导致的未种植错误 | 447 | 全部排除 |
| 成功收割 | 91 | 全部保留 |
| 其他收割错误 | 16 | 全部保留，超出本规则范围 |

所有排除依据都与原始 HTTP 输入中的工具结果、参数、执行状态和时间精确匹配。
旧 trace 哈希前后相等。此次新增模型请求 0、真实工具执行 0。

上述是历史参数的可表达性检查，**不是**新 Agent 运行。不能宣称节省了 447 次
实际调用、提升了耗时/成功率，也不能判断删去这些参数后模型会选哪个动作。

## 已完成的接口与轨迹验证

Agent 先让 Jev 选择工具。选择收割后，规划器从本次运行已经执行的公开反馈推导
合同，将限制用于起点候选、条件终点和最终完整参数验证。对其他工具不增加此合同。
规划器不读取 task、evaluator 或世界私有对象来决定应收哪个范围。

`parameter_plan` 保存该次冻结的状态合同和来源。独立轨迹验证器基于事件前缀重新
计算，再核对合同、每一阶段候选、最终参数与执行链；不会直接信任记录中的
`excluded_ridges`。删去合同、篡改限制或塞回被排除的完整参数，都能被检查发现。
manifest 保存策略名称与模块哈希。

新增测试实际调用原生收割工具，模型决策使用脚本且网络禁用：

- 纯 Jev 的两种 state 和 Hybrid 均依次收割 0–3、4–7，第二次不再提供 0–3。
  两轮共 7 次脚本决策，没有额外模型修复或刷新步骤。
- 关闭策略时，原来的重复 0–3 选择仍然执行并收到原生错误，验证默认行为保留。
- 全排除的合成输入仅测试控制器边界：连续三次选择收割会触发现有
  `repeated_parameter_failure`，没有工具执行或 FINISH。这不是真实全田收割证据，
  也没有解决所有类型的无候选循环。
- 纯 Jev 与 Hybrid 各一个完整脚本 episode 均通过轨迹验证和按原时间动作回放，
  模型 HTTP 次数为 0。只收割了 8 垄，不宣称完成场景的全田收储任务。
- `tests/jev` 与迁移 smoke 共 **821 项通过**，9.33 秒；所有网络连接被禁止。

`harvest_range_menu` 是离线枚举辅助函数，返回的 `runtime_enabled=false` 表示
调用该函数本身不启用 Agent；实际启用依赖上述配置和 `bind_harvest_contract`。

## 仍需验证

1. 真实模型在受限菜单中的后续选择、耗时、上下文大小和任务质量仍未知。
   合同会增加少量输入；不能只凭候选数减少推断总 token 降低。
2. 当前合同不检查成熟度、水分、天气、油料、粮箱容量或仓储，不保证所有收割成功。
   同样不覆盖其他工具的空耗循环。
3. 真实试验另行预登记。当前批准的 78 场实验和 4 次冻结请求均不包含此策略。
