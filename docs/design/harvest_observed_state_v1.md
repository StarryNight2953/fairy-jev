# Jev 收割参数：基于可见状态的离线适配原型

本分支从正在实验的 `ac92e1d` 分离。`harvest_contract.py` **尚未接入
Agent/CandidateResolver**，因此不会改变当前 78 场 Jev 覆盖实验。它也没有修改
Hybrid、Prompt、任务、验收器或原生工具。当前默认策略完全不变。

## 直接证据与范围

冻结的 12 个历史场景中有 447 次收割返回
`All ridges must be planted before harvest`。这些请求选择的范围已经出现在
此前成功返回的 `harvested_ridges` 中；相关原始结果也实际进入了 Jev HTTP 输入。
原生 `TractorApp.harvest` 检查的是所选范围内的 `planted`，不是要求整个农场仍然
全部已种植。成功收割使所选垄 `planted=False`。因此该样本存在可由公共反馈
识别的参数前置条件冲突，而非反馈未送入模型。

这不是模型内部原因的证明，也不表示所有循环都具有同一个原因。

## 原型合同

- 输入是单次 episode 内按 `event_id` 严格排序的公开事件、已声明的垄界与作业宽度。
  不读取模拟器、checkpoint、oracle 或任务评分字段。
- 成功且实际执行的收割反馈只排除返回的 `harvested_ridges`。不从请求范围推定
  全部执行成功，不从 LLM 摘要推定事实。原始结果与事件 ID 随规则保留。
- 公开范围查询若明确返回布尔 `planted`，可更新限制；不将 NDVI、生育阶段或
  `harvested=False` 转换为已种植。
- 播种/补种移除受影响垄的旧限制；这仅表示需要重新判断，**不证明成熟可收**。
  模糊的播种错误也保守撤销相关限制，避免部分执行后永久误封。
- 整地、环境通知、显式状态失效事件撤销旧限制。没有解释通知文本的隐含语义。
  这是保守策略，可能使原先已知的无效范围重新出现。
- 未知垄仍保留。起点与终点共享同一份限制；终点不小于起点，不超过既有每趟宽度，
  也不会跨过中间已排除垄。不把整片范围缩成一个自动选择的动作。
- 无合法范围时返回 `needs_context`。不自动 FINISH、不执行刷新工具，不替模型
  选择其他动作。

当前作物状态失效路径依据该提交中 FAIRY 的种植、补种、起垄和收割实现审查。
若增加其他可以改变 `planted` 的工具、外部修改或跨 episode 历史，必须补充失效
合同；本原型不声称适用于任意农场工具或任意外部并发修改。

## 离线结果

24 项测试通过，覆盖空状态、整段候选覆盖、范围中间空洞、上下界、起止顺序、
重播/补种、错误与未执行区分、显式观测覆盖、通知/生命周期失效、非法数据、
输入不变和全范围排除。测试禁止网络访问。

对冻结的 12 份 trace，审查发生在每次原始工具选择请求之前，不使用之后的结果
来构造该次候选。共检查 554 次历史收割：

| 历史调用结果 | 次数 | 原参数在新菜单中的情况 |
| --- | ---: | --- |
| 已收割范围导致的未种植错误 | 447 | 全部排除 |
| 成功收割 | 91 | 全部保留 |
| 其他收割错误 | 16 | 全部保留，超出本规则范围 |

所有排除依据都与原始 HTTP 输入中的工具结果、参数、执行状态和时间精确匹配。
旧 trace 哈希前后相等。此次新增模型请求 0、真实工具执行 0。

上述是历史参数的可表达性检查，**不是**新 Agent 运行。不能宣称节省了 447 次
实际调用、提升了耗时/成功率，也不能判断删去这些参数后模型会选哪个动作。

## 接入前仍需完成

1. 为新可选策略接入参数起点、终点以及最终参数验证，旧策略保持可回放。
2. trace 中冻结状态依据，独立验证器从已执行公开事件重新推导，不能直接信任
   Agent 声明的过滤结果。
3. 明确 `needs_context` 的可见反馈和下一轮行为；避免把重复工具执行变成重复
   选择无候选工具。
4. 真实试验另行预登记。当前批准的 78 场实验和 4 次冻结请求均不包含此策略。
