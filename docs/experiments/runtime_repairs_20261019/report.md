LLM超时优先级为：显式配置 `timeout` → 环境变量 `FAIRY_LLM_REQUEST_TIMEOUT_S` → 默认1800秒。空值回退，无效值（零、负数、NaN、无穷）在构造时拒绝。当前Qwen配置明确填写1800，因此覆盖环境默认。实验传输层仍把各HTTP阶段的超时收紧到本场剩余时间：离线验证剩余7200秒时为1800，剩余250秒时为250。SDK原生重试次数和Updater重试规则没有调整；TypeSafe请求超时仍为30秒。

这修复了已知的30秒配置过短问题，**不证明服务端生成变快，也不保证真实请求均可完成**。本轮没有发起真实Qwen或Jev验收。历史JSON中的30秒、600秒及1800秒仍代表当时实际配置。

任务输入错误来自 `build_management_l1_flow` / `build_management_l2_flow` 的 `briefing_text` 与 `prefix` 位置传反。15处调用已修正，原任务文本、工具动作参数和验收规则保留。全部32处管理流程调用都已审查；另17处原本正确。预检新增窄范围校验，拒绝空任务或整条仅含 `o_*` 的内部标识，避免正常初始化掩盖错误输入。它不判断任务语义是否正确。逐场旧标识、新任务原文、文件路径、哈希及事件ID见 `task_briefing_fixes.json`。
