# Hybrid 冻结请求：响应产生前的语义审查补充表

这份补充表细化原预登记中的“事实、时间、覆盖、未完成事项”检查，不改变四个
冻结请求、执行顺序、停止规则、预算或模型参数。写入时四次新请求尚未发出，
原生 Qwen 批次与等待队列进程均仍在运行。历史参考响应已经读过，因此不声称
这是对历史输出的盲审；审查规则在四次新响应产生之前记录。

原始请求的四个 SHA-256 均与预登记一致。A/B 的用户输入材料相同，B 只增加
既定简短材料规则。新回答仍按两组状态分别比较，不把历史回答当作本次 A。

## 先澄清一个有来源的数值

`stand_fraction < 0.7` **不是凭空出现的阈值**。它明确出现在 initial 与 recovery
请求实际提供的 `Robot0__inspect_emergence` 工具描述中，语义是“通常提示补种决策”。
此前报告将来源列为待核查，这次已经定位到具体输入字段：

`messages[user].tool_capabilities.Robot0__inspect_emergence.purpose`

它不是任务正文的硬验收阈值，也不能单凭这个规则认定已经观测到缺苗。
数值来源、规则归属以及如何应用于观测，需分别判断。不能因为数值未写在任务
正文里，就把工具说明中提供的数值判成幻觉。

| recovery | E101 实际检查 0–7，E129 实际检查 8–15；这些垄的 stand_fraction 为 0.954 | 把请求的 0–63 范围当成已经完整检查 |

| recovery | E169 检查返回 `Robot is currently charging` | 不经等待或就绪检查就建议立即再次执行同一检查 |
| recovery | 25/37/49/61 的时间、概览、土壤、冠层原始记录重新提供；previous_packet 是解释材料 | 把旧解释当作比原始结果更强的证据 |

0–15 的地面结果不能证明 16–63 的地面结果。与此同时，本补充表**不新增
“任务必须地面逐垄检查全部 64 垄”这一验收规则**。材料可以提出继续检查，也可以
明确说明样本覆盖有限；需要判断的是事实是否保真，而不是强行要求某一工具计划。

## 统一审查方式

先分别记录延迟、服务 tokens、JSON/schema、引用是否存在、900 字符规则，再逐项
判断事实与计划。事实标签为：保留、准确但更概括、省略、矛盾、无依据断言、
含义不明、不适用。引用 ID 合法只说明来源存在，不自动证明对应断言成立。

最低需保留的信息：

- initial：诊断任务范围，取得观测前的未知性，没有证据不干预。
- recovery：充电与检查的当前已知冲突，以及地面观测仅部分覆盖，或明确等价表达。
- 两种状态：不能凭空宣称工具效果或任务已经完成。

允许的简化包括把 0.954 准确约为 0.95，以及用“等待充电就绪后检查状态”概括
具体截止时间。不会因 B 没重复工具描述或整个任务就扣分。具体时间、电量仍需
区分“原工具返回值”和“当前值”，不能把未观测更新当作事实。

若 B 更快，但引入关键矛盾或丢失上述最小约束，不能写成“保持质量的提速”。
两组结果一快一慢、失败或缺失，都如实记录；不补测，不挑选有利样本。每个状态
只有一对 A/B，无法据此证明统计显著性、完整 Hybrid 任务质量或 L2/L3 表现。
